## 2026-09-21 — M1 정적 공유 (`d00c0aa`)

판을 짧은 배열로 포장해 deflate로 압축하고 주소용 문자로 바꿔 `#b=…`에 담는다.
**해시를 쓰는 이유가 두 가지다** — 정적 호스팅에서 서버 설정 없이 동작하고,

판 id를 **내용에서 뽑아낸다**(FNV-1a). 서버 없이도 "같은 판"을 판별할 수 있어서
진행 상황을 판별로 저장할 수 있다. 섞기 시드는 **판 id + 참가자 이름**에서 뽑아
새로고침해도 자리가 그대로다. 저장한 체크가 엉뚱한 칸에 붙는 사고를 막기 위한 장치다.

확인한 것: 재현성, 다른 이름이면 다른 배치, 공짜 칸 위치 고정, 빙고 판정과 강조,
손상된 링크 안내, 4×4 공짜 칸 잠김, 크기별 필요 문항 수.

### 섞기와 배치의 충돌

칸을 직접 배치하게 되면서 섞기와 부딪힌다. 자리를 정해도 섞기가 켜져 있으면 참가자는
다른 자리로 받는다. 기능을 없애는 대신 **채우기 화면 맨 위에서 상태를 알려주는 쪽**을 택했다.
섞기를 끄고 배치한 판이 참가자에게 칸 하나까지 똑같이 전달되는 것을 확인했다.

## 2026-09-30 — 간소화와 오프라인

사용자 요청: *"기능 확 간소화할 거야. 링크를 받은 사람이 빙고판을 작성할 수 있고, 저장해서
인터넷이 안 되는 상황에서도 빙고판을 수정하고 체크할 수 있었으면."*

무엇을 걷어낼지는 결과가 갈리는 선택이라 물었다. 사용자가 고른 것:

- 링크를 보내는 사람은 **제목·크기만** 정한다 (지금까지의 "각자 판 만들기"와 같은 흐름)
- 남길 것: **승리 조건 N줄, 크기 선택, 이름 입력.** 가운데 공짜 칸은 고르지 않아 걷어냈다

### 바꾼 것

- 공유판 모드 · 섞기 · 여분 · 시드 배치 · 공짜 칸 제거. `board.ts`에는 판정만 남았다
- 내 판을 **링크 하나에 레코드 하나**(이름 · 문항 · 체크)로. 이름은 표시용이 됐다 — 전에는 이름마다 판이 따로였다
- 진행 중 **문항 고치기.** 체크는 칸 자리에 남는다
- 처음 화면에 **이 기기에 저장된 판 목록.** 오프라인에서 링크 없이도 돌아올 길이다
- **저장 실패를 화면에 알린다.** 저장이 핵심 약속이 됐으니 조용히 넘기면 안 된다
- `navigator.storage.persist()`로 브라우저에 저장분을 지우지 말아 달라고 부탁한다
- "처음부터" 버튼 이름을 **"체크 모두 풀기"**로 — 문항 고치기가 생기면서 무엇을 지우는지 모호해졌다

### 설계하다 찾은 문제 — 설정이 같으면 링크도 같다

링크에서 문항이 빠지니 제목 · 크기 · 줄 수가 같으면 링크가 똑같아진다. 기본값으로 초대를 두 번 만들면
**서로 다른 모임의 판이 한 기기에서 하나로 합쳐진다.** 링크마다 임의 값(`nonce`)을 붙였다.
링크 형식 3판 — 끝 자리에 덧붙이고, 안 쓰게 된 3~6번 자리는 고정값으로 남겼다(계약 3).

### 오프라인 — workbox 대신 직접

`vite-plugin-pwa`는 Vite 8을 지원하지만 workbox를 통째로 끌고 온다. 앱 파일이 4개뿐이라, 빌드 끝에
dist를 훑어 `sw.js`를 만드는 작은 플러그인(`vite.config.ts`의 `offlineCache`)과 짧은 서비스 워커로 충분했다.

웹 앱 매니페스트("홈 화면에 추가"로 설치)는 넣지 않았다. 아이폰에서 설치한 앱은 사파리와 저장소가
분리되어, 사파리에서 채운 판이 설치한 앱에서 보이지 않는다.

### 서버를 실제로 꺼 보고서야 잡힌 버그 — `Vary: Origin`

preview 서버를 끄고 새로고침하자 **화면이 하얗게** 떴다. `index.html`은 캐시에서 나왔는데 JS · CSS만
실패했다. 서버가 `Vary: Origin`을 붙이는데, 캐시에 받아 둘 때의 요청엔 `Origin`이 없고 페이지가
`crossorigin` 속성으로 부를 땐 브라우저가 `Origin`을 붙인다. `Vary`가 달라 **캐시에 있는데도 못 찾았다.**
`ignoreVary: true`로 주소만 보고 찾게 고쳤다.

**온라인에서는 네트워크가 받아 줘서 전혀 드러나지 않았다.** 그대로 배포됐으면
"오프라인에서 된다"는 약속이 통째로 거짓이었다.

같은 자리에서 하나 더: 버전 해시가 dist만 보고 서비스 워커 본체는 안 봐서, 서비스 워커만 고친 빌드가
**같은 캐시 이름**을 썼다. 본체도 해시에 넣었다.

CLAUDE.md의 좀비 서버 함정 때문에, 서버를 끈 뒤 **포트가 진짜 닫혔는지**와 **캐시에 없는 주소 요청이
실패하는지**까지 보고 나서야 오프라인이라고 판단했다.

### 검증 방식에 대한 솔직한 기록

판정 · 링크 · 저장 규칙은 `npm test`가 자동으로 지킨다. 화면과 오프라인은 브라우저를 스크립트로
조작해 확인했다 — 서버를 **실제로 끄고.**

**실제 폰에서는 확인하지 않았다.** 칸 크기나 입력창 위치 같은 손맛, 그리고 특히
**아이폰 카카오톡 인앱 브라우저가 서비스 워커를 지원하는지**와 사파리가 오래 안 쓴 사이트의
저장분을 지우는 정책은 실기기에서 봐야 한다.
