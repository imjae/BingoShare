# BingoShare 기획서

커스텀 빙고판을 만들어 **링크 하나로 공유**하고, 각자 진행하면서 **서로의 현황**을 보는 웹앱.

- 최초 작성: 2026-09-21
- 상태: 기획 중 (코드 미착수)

---

## 1. 결정된 것

| 항목 | 결정 |
|---|---|
| 공유 후 동작 | 참가자가 **각자 자기 판을 진행**하고, 별도의 **현황판**에서 서로의 진도를 본다 |
| 칸 섞기 | **판을 만들 때 선택** (섞기 on/off 토글) |
| 호스팅 | **무료 정적 호스팅 우선** |
| 방식 (2026-09-21 추가) | **두 가지 중 선택** — 하나의 판 공유 / 각자 판 만들기 |
| 승리 조건 (2026-09-21 추가) | **N줄을 먼저 만든 사람이 승리.** N은 판을 만들 때 정한다 |

### 방식 두 가지

|  | 하나의 판 공유 (`shared`) | 각자 판 만들기 (`own`) |
|---|---|---|
| 문항을 정하는 사람 | 만든 사람 | **참가자 각자** |
| 링크에 담기는 것 | 설정 + 문항 전체 | 설정만 (문항 없음) |
| 링크 길이 | 문항 24개에 약 520자 | **약 80자** |
| 칸 섞기 | 선택 | 해당 없음 (자기 문항, 적은 순서대로) |

`own`에서 참가자가 적은 문항은 **그 사람 브라우저에만** 저장된다. 한 번 정하면 바꾸지 않는다 —
바꾸면 이미 체크해 둔 칸의 내용이 달라지기 때문이다.

### 가정 (명시)

- **모바일 우선**으로 만든다. 빙고는 모여서 폰으로 하는 물건이고, 공유 링크도 대부분 폰에서 열린다.
- **로그인 없음.** 참가는 이름만 적고 들어간다. 계정 시스템은 만들지 않는다.

## 2. 짚고 갈 모순과 해결

**현황판은 서버가 필요하고, 정적 호스팅은 서버가 없다.**

해결은 둘을 분리하는 것이다.

- **호스팅**은 정적 그대로 둔다 (GitHub Pages / Cloudflare Pages — 공짜, 무기한).
- **데이터**만 무료 BaaS에 맡긴다 (Supabase 무료 티어). 브라우저가 직접 호출하므로 서버를 직접 굴릴 일이 없다. 관리 부담은 계정 하나.

그리고 이걸 처음부터 다 만들지 않는다. **단계를 자른다.**

| 단계 | 서버 | 공유 방식 | 현황판 |
|---|---|---|---|
| **M1** | 없음 | 판 데이터를 **링크 주소 안에 통째로** 담는다 | 없음 (각자 진행만) |
| **M2** | BaaS | 짧은 링크 `/b/<id>` | 있음 |

M1만으로도 "커스텀 빙고판을 링크로 공유한다"는 목적은 달성된다. M2는 그 위에 얹는다.

> **설계 원칙:** 진행 상황을 읽고 쓰는 통로를 **어댑터 하나**로 좁혀둔다.
> M1에서는 그 어댑터가 브라우저 저장소를 보고, M2에서는 BaaS를 본다. 화면 코드는 건드리지 않는다.

## 3. 핵심 흐름

```
[만들기]  제목 · 칸 문항 입력 · 크기 · 섞기 on/off
    ↓
[공유]    링크 복사 / QR
    ↓
[참가]    링크 열기 → 이름 입력 → 내 판 생성
    ↓
[진행]    칸 탭해서 체크 → 빙고 줄 완성되면 표시
    ↓
[현황]    참가자별 달성 칸 수 · 빙고 줄 수 (M2)
```

---

## 4. 규칙

- **크기**: 3×3 / 4×4 / 5×5
- **FREE 칸**: 5×5일 때 가운데를 공짜 칸으로 할지 선택
- **빙고 판정**: 가로 · 세로 · 대각선
- **섞기 시드**: 참가자 이름을 해시해서 시드로 쓴다. 같은 사람이 새로고침해도 **배치가 그대로**여야 한다.
- 문항 개수가 칸 수보다 많으면 → 그 중에서 뽑아 쓴다 (판마다 문항 구성 자체가 달라짐)
- 문항 개수가 칸 수와 같으면 → 순서만 섞는다

---

## 5. 데이터 모델

```
Board                        # 판 정의 (만든 사람이 소유)
  id          문자열
  title       제목
  size        3 | 4 | 5
  cells       문항 배열
  shuffle     참가자마다 섞을지
  freeCenter  가운데 공짜 칸 여부

Participant                  # 참가자
  name        이름 (식별자 겸용)
  seed        name에서 파생, 배치 고정용

Progress                     # 진행 상황
  boardId
  participant
  checked     체크된 칸 인덱스 목록
  updatedAt
```

`Board`는 만든 뒤 바뀌지 않는다(불변). 문항을 고치면 **새 판**이 된다 — 진행 중인 참가자들의 배치가 어긋나는 걸 막기 위해서다.

## 6. 링크 설계

### M1 — 서버 없음

```
https://<도메인>/#b=<압축한 Board를 주소용 문자로 인코딩>
```

- `#` 뒤에 두는 게 중요하다. 해시는 **서버로 전송되지 않아** 접속 기록에 판 내용이 남지 않는다.
- 압축 후 주소 길이를 **2000자 이내**로 유지한다. 대부분의 메신저·브라우저가 안전하게 다루는 선이다.
- 문항이 많아 넘치면 사용자에게 알리고 문항을 줄이도록 안내한다.

### M2 — 짧은 링크

```
https://<도메인>/b/<id>
```

판은 BaaS에 저장하고 링크는 id만 담는다. 길이 제한이 사라지고, 현황판이 가능해진다.

## 7. 화면 목록

| 화면 | 내용 |
|---|---|
| **만들기** | 제목, 문항 입력(여러 줄 붙여넣기 지원), 크기, 섞기 토글, FREE 칸 토글 |
| **공유** | 링크 복사 버튼, QR 코드, 길이 경고 |
| **참가** | 이름 입력 → 내 판으로 |
| **내 판** | 빙고 격자, 탭으로 체크, 완성된 줄 강조 |
| **현황** | 참가자 목록 + 달성 칸 수 + 빙고 줄 수 (M2) |

문항 입력은 **여러 줄 붙여넣기**를 꼭 지원한다. 25칸을 한 칸씩 타이핑하게 두면 아무도 안 만든다.

## 8. 기술 스택 제안

- **Vite + React + TypeScript** — 정적 빌드가 나오고, 배포가 파일 업로드로 끝난다
- **Tailwind CSS** — 모바일 우선 레이아웃을 빠르게
- **fflate** — 링크에 담을 판 데이터 압축
- **배포**: Cloudflare Pages 또는 GitHub Pages
- **M2**: Supabase (Postgres + 실시간 옵션)

- **M1 — 정적 공유** ✅ 2026-09-21. 만들기 → 링크 공유 → 참가 → 진행. 서버 없음. **이제 실제로 써볼 수 있다.**

### M1에서 실제로 만든 것

| 파일 | 맡은 일 |
|---|---|
| `src/lib/encode.ts` | 판 ↔ 링크 주소. 압축 후 주소용 문자로. 판 id도 내용에서 뽑는다 |
| `src/lib/board.ts` | 시드 섞기, 배치 확정, 빙고 판정, 붙여넣기 해석 |
| `src/lib/storage.ts` | **진행 상황을 읽고 쓰는 유일한 통로.** M2에서 여기만 갈아끼운다 |
| `src/lib/route.ts` | 해시 한 줄로 화면 가르기 |
| `src/screens/CreateScreen.tsx` | 만들기 |
| `src/screens/ShareScreen.tsx` | 공유 |
| `src/screens/PlayScreen.tsx` | 참가 + 진행 |
| `src/components/BingoGrid.tsx` | 빙고 격자 |

확인한 것: 같은 이름이면 새로고침해도 배치·진행 그대로, 다른 이름이면 배치가 달라지되
문항 구성은 같음, 가운데 공짜 칸 위치 고정, 가로 빙고 판정과 강조, 손상된 링크의 안내 문구,
4×4에서 공짜 칸 잠김, 크기별 필요 문항 수(3×3=8, 4×4=16, 5×5=24).

### M1.5 — 방식 선택과 승리 조건 ✅ 2026-09-21

- `own` 모드 추가. 초대 링크에는 설정만 담고, 문항은 참가자가 각자 채운다
- 승리 조건(`targetLines`) 추가. 달성하면 판 위에 알림이 뜬다
- 링크 형식을 2판으로 올리되 **1판 링크도 계속 열린다** (모드 `shared`, 1줄 승리로 읽는다)
- 고친 것: 링크를 바꿔 이동할 때 앞 판의 참가자 이름과 문항이 남던 문제
  (화면에 `key`를 주지 않아 React가 같은 화면을 재사용하고 있었다)

> **한계 — 승부 판정.** 서버가 없으므로 앱은 **내가** 조건을 채웠다는 것만 안다.
> 누가 먼저였는지는 같이 하는 사람끼리 확인해야 한다. 자동 판정은 M2 현황판의 몫이다.

### M1.6 — 판 위에서 칸을 눌러 채우기 ✅ 2026-09-21

문항을 한 줄에 하나씩 타이핑하는 방식은 폰에서 쓰기 나빴다. **빈 판을 먼저 보여주고
칸을 눌러 그 자리에 들어갈 문항을 적는** 방식으로 바꿨다 (`components/BoardEditor.tsx`).

- 만들기를 **설정 → 판 채우기** 두 단계로 나눴다. 설정 화면이 짧아지고, 채우기에 집중할 수 있다
- 아무 칸이나 눌러도 되고, 적고 **확인**을 누르면 다음 빈 칸으로 넘어간다. 다 채우면 입력이 닫힌다
- 칸을 고르면 입력칸에 자동으로 초점이 간다 — 폰에서 키보드가 바로 올라온다
- 목록이 이미 있는 사람을 위해 **여러 줄 붙여넣기**를 보조 수단으로 남겼다. 위 칸부터 순서대로 채운다
- 칸 수를 넘겨 붙여넣으면 **여분**으로 따로 모아 두고, 참가자마다 뽑히는 문항이 달라진다고 알린다
- 각자 판 모드의 문항 채우기도 같은 화면을 쓴다

> **섞기와의 관계.** `shared` + 섞기 on이면 내가 놓은 자리는 참가자에게 그대로 가지 않는다.
> 채우기 화면 맨 위에서 이 사실을 알린다. 섞기를 끄면 놓은 자리 그대로 전달된다.

## 10. 아직 안 정한 것

- **참가자 식별**: 이름만으로 충분한가? 같은 이름 둘이면? (브라우저에 참가자 키를 저장하는 방안)
- **판 수정**: 만든 뒤 문항을 고치고 싶을 때 — 새 판으로 강제할지, 진행 중 참가자를 마이그레이션할지
- **현황판 범위**: 칸 수만 볼지, **어느 칸을 찍었는지까지** 볼지 (후자가 훨씬 재밌지만 눈치싸움이 사라짐)
- 공개 갤러리 / 템플릿 공유 기능 — 당장은 없음
- 도메인을 살지, 무료 하위 도메인을 쓸지
